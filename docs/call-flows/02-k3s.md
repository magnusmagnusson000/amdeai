# Call flow: k3s (Kubernetes runtime)

**Script:** `scripts/02-kubernetes.sh`  
**Binary:** `/usr/local/bin/k3s`

Provides the **control plane and kubelet** where operators, Helm releases, and the GPU device plugin run.

## Install flow (script `02-kubernetes.sh`)

1. **Preflight:** Reboot check after `01-host-rocm.sh` (GRUB changes need reboot).
2. **Swap off:** Required for kubelet stability.
3. **k3s install** (requires sudo):
   ```bash
   curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="server \
     --node-ip=<NODE_IP> \
     --tls-san=<NODE_IP> \
     --disable=traefik \
     --disable=servicelb \
     --kubelet-arg=--allowed-unsafe-sysctls=net.* \
     --kube-apiserver-arg=allow-privileged=true" sh -
   ```
4. **Kubeconfig:** Copied to `~/.kube/config`.
5. **Local registry:** Deployment + NodePort Service on **32000** (`/etc/rancher/k3s/registries.yaml` mirrors `localhost:32000` and `<NODE_IP>:32000`).

**Fallback:** Without passwordless sudo, script uses **k3d** (Docker-backed cluster `eai`).

## Downward (API request)

1. `kubectl` → **kube-apiserver** (embedded in k3s).
2. Controllers reconcile Deployments, DaemonSets, CRDs.
3. **kubelet** + **containerd** start pods.
4. **Flannel CNI** routes pod traffic.

## Chat-related traffic

- AIWB / AIM / ingress pods run **inside** the cluster.
- Workbench chat to local Gemma: backend egress to **host IP:8080** (llama-server).
- Cluster vLLM: traffic stays in-cluster via Service/Ingress.

## Upward (status)

- `kubectl get nodes`, `kubectl get pods -A`
- Pod logs for operator debugging

## Verification

```bash
kubectl get nodes
kubectl get svc -n kube-system registry
curl -sf http://localhost:32000/v2/  && echo "registry OK"
```

## Not involved

Token generation in host `llama-server` — only HTTP **clients** in the cluster may traverse k3s networking to reach the host.
