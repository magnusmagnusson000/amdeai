# Call flow: k3s (Kubernetes runtime)

**Binary:** `/usr/local/bin/k3s` (or install script path)

Provides the **control plane and kubelet** where operators, Helm releases, and device plugin run.

## Downward (API request — generic)

1. `kubectl` / client-go → **kube-apiserver** (embedded in k3s server).
2. Admission, authn/z, persistence in **etcd** (embedded).
3. **Controllers** (deployment, replicaset, endpoint, etc.) reconcile desired state.
4. **kubelet** on node pulls images via **containerd**, starts pods.
5. **CNI (Flannel)** routes pod network.

## Chat-related traffic

- **AIWB / AIM / ingress pods** communicate inside cluster network.
- Egress to **host IP:8080** leaves cluster via node routing (hostNetwork or node IP Service).

## Upward (status)

- Pod status → Deployment → UI health checks.
- `kubectl logs` for debugging.

## Chat prompt path

**Transport and tenancy** for control-plane and UI pods; optional path for in-cluster inference Services.

## Not involved

Token generation inside llama.cpp on host — only the **HTTP client pod/network** may traverse k3s networking.
